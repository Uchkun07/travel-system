摘 要

本研究针对当前通用型旅游平台存在的信息过载和推荐精准度低等问题，设计并实现了一个基于Vue3+SpringBoot的个性化旅游平台。研究采用前后端分离架构，前端运用Vue3+TypeScript技术栈，充分利用其组件化开发与高效渲染特性构建用户界面，后端基于SpringBoot框架开发，结合其轻量化与易扩展优势构建高可用系统。通过文献研究法梳理技术现状，运用需求分析法结合用户访谈与竞品分析形成结构化需求文档，采用原型设计法利用Figma构建系统原型验证交互逻辑。系统设计阶段完成了架构设计与数据库建模，确保功能模块化与数据结构优化。开发过程中采用迭代开发法，分步实现了用户管理、景点展示、个性化推荐等核心功能模块，并集成协同过滤算法提升推荐精准度，引入模拟退火算法优化行程规划能力。

平台核心功能涵盖用户注册登录、景点信息展示、个性化推荐、智能行程规划等模块。前端实现了景点筛选、收藏管理等功能，通过封装通用组件优化系统性能；后端开发RESTfulAPI接口，支持完整的用户管理、景点管理与权限控制体系，并引入Redis缓存机制显著提升系统运行效率。研究特别注重算法集成，通过协同过滤算法实现基于用户行为的个性化景点推荐，运用模拟退火算法进行旅游路径优化。测试阶段采用多元化策略，结合黑盒测试与白盒测试方法，使用Apifox、JUnit、JMeter等专业工具进行接口测试、单元测试和性能测试，通过全面的安全检测与性能调优确保系统稳定运行。研究成果为旅游信息化系统开发提供了完整的技术解决方案，有效解决了传统平台个性化服务不足的问题，为旅游资源整合与个性化服务提供了重要参考。

ABSTRACT

This study addresses the issues of information overload and low recommendation accuracy in current general tourism platforms, and designs and implements a personalized tourism platform based on Vue3+SpringBoot. The research adopts a front-end and back-end separation architecture, with the front-end utilizing Vue3+TypeScript technology stack to fully utilize its component-based development and efficient rendering features to build user interfaces, and the back-end developed based on the SpringBoot framework, combining its lightweight and easy to scale advantages to build a highly available system. By using literature research method to sort out the current status of technology, using requirement analysis method combined with user interviews and competitor analysis to form a structured requirement document, and using prototype design method and Figma to construct a system prototype to verify the interaction logic. The system design phase has completed the architecture design and database modeling, ensuring functional modularization and data structure optimization. During the development process, an iterative development method was adopted to gradually implement core functional modules such as user management, attraction display, and personalized recommendation. Collaborative filtering algorithms were integrated to improve recommendation accuracy, and simulated annealing algorithms were introduced to optimize travel planning capabilities.

The core functions of the platform include user registration and login, display of scenic spot information, personalized recommendations, intelligent itinerary planning, and other modules. The front-end has implemented functions such as scenic spot screening and collection management, and optimized system performance by encapsulating universal components; Backend development of RESTful API interface, supporting complete user management, attraction management, and permission control system, and introducing Redis caching mechanism to significantly improve system operation efficiency. The research places special emphasis on algorithm integration, implementing personalized attraction recommendations based on user behavior through collaborative filtering algorithms, and using simulated annealing algorithm for tourism path optimization. The testing phase adopts a diversified strategy, combining black box testing and white box testing methods, using professional tools such as Apifox, JUnit, JMeter for interface testing, unit testing, and performance testing. Through comprehensive security checks and performance tuning, the system ensures stable operation. The research results provide a complete technical solution for the development of tourism information systems, effectively solving the problem of insufficient personalized services on traditional platforms, and providing important references for the integration of tourism resources and personalized services.

# 绪论

## 研究背景与意义

随着全球旅游市场的全面复苏，文旅消费已成为国民经济的重要支柱。数字化技术（如移动互联网、大数据、人工智能）正深度重塑旅游业。旅游数字化服务已从静态信息展示演进为动态决策支持。用户在出行前需要综合考虑景点偏好、地理分布、交通方式、费用预算与时间约束，而传统平台通常仅提供单点检索或固定模板推荐，难以覆盖复杂决策场景。本课题的研究意义体现在以下三个方面：

1\. 理论意义：将启发式优化算法引入旅游路径推荐，探索“业务约束 + 实时地图数据”的融合建模方法。

2\. 工程意义：构建完整前后端分离体系，形成从数据采集、业务服务到管理运营的全链路实现路径。

3\. 应用意义：提升用户路径规划效率与结果可解释性，降低平台运营管理成本，增强系统可持续迭代能力。

## 国内外研究现状

在国外研究中，旅游推荐系统已广泛应用协同过滤、内容推荐与图模型方法，并逐步引入强化学习、图神经网络等技术，以提升推荐精度和长期收益。然而，面向真实出行决策的研究仍存在两类问题：一是对地理路网与动态交通数据融合不足，二是工程落地时对权限治理与运营后台支持不完整。

国内研究在智慧文旅与城市大脑背景下发展迅速，主流系统更关注景区导览、票务协同和文旅数据展示。针对个性化路径规划的研究虽然逐步增多，但在本科项目与中小规模平台实践中，常见问题包括：算法与业务系统割裂、推荐与路径链路不统一、管理端能力薄弱、系统可维护性不足。

综合来看，现有研究为本文提供了理论基础，但在“真实地图数据驱动的路径优化 + 工程化管理闭环”方面仍有提升空间。

## 研究内容与研究方法

本文围绕“基于 Vue3 + SpringBoot 的个性化旅游平台”开展研究，核心内容如下：

1\. 需求建模与功能规划：针对当前旅游平台存在的个性化推荐能力不足、卢西安规划不够智能、管理后台权限管控不精细等问题，从用户端与管理端双视角梳理功能与非功能需求。

2\. 系统架构设计与数据库设计：采用前后端分离架构，前端基于 Vue3 构建交互界面，后端基于 SpringBoot 提供接口服务，数据库采用 MySQL 完成数据持久化。设计并优化数据表结构，针对景点多类别归属需求，建立景点与类型的多对多关联关系，保证数据规范与可扩展性。

3\. 核心算法设计与实现：基于内容的推荐算法与基于模拟退火算法进行路径优化，结合高德 API 获取真实时间与费用。

4\. 系统功能模块实现：完成用户端与管理端全功能开发。用户端包含注册登录、热门城市、景点详情、收藏、路线规划、首页滚动加载推荐等模块；管理端基于 RBAC 权限模型，实现景点管理、订单管理、轮播图管理、权限分配与数据大屏可视化等功能。

5\. 系统测试与效果评估：搭建测试环境，开展功能测试、性能测试与兼容性测试。从路径优化率、偏好匹配率、推荐准确率、系统响应时间等维度，对算法效果与系统稳定性进行客观评估。

研究方法采用文献分析法、需求分析法、原型驱动法、对比实验法与工程验证法。

# 相关技术与理论基础

## 系统总体技术栈

本系统采用前后端分离架构进行开发，整体技术栈选取以成熟稳定、轻量高效、易扩展、高并发支持为原则，结合当前主流 Web 开发技术与算法模型完成平台构建。技术栈覆盖前端展示、后端服务、数据存储、中间件、第三方接口与核心算法六大层面，各层技术相互协同，形成完整的系统开发与运行支撑体系。

## 前端技术基础

### Vue3 与组合式 API

本系统用户端与管理端均基于 Vue3 渐进式框架构建。Vue3 底层采用基于 Proxy 的数据劫持机制，相较于 Vue2 的 Object.defineProperty，大幅提升了响应式系统的性能与深层对象监听的效率。 在代码组织层面，项目全面拥抱组合式 API（Composition API）。相比传统的选项式写法（Options API），组合式 API 打破了生命周期钩子对逻辑的强制割裂，允许开发者按业务功能（如路线规划逻辑、用户状态管理等）将相关变量与方法封装为独立的 Hooks 模块。这种范式在处理旅游推荐系统复杂页面交互时，表现出了卓越的逻辑复用能力、类型推导友好性以及更优的可测试性。

### TypeScript 与工程约束

在前端工程化实践中，系统引入 TypeScript（简称 TS）作为 JavaScript 的超集。TS 提供的静态类型检查机制，能够在编译阶段提前暴露潜在的类型不匹配错误。在本项目中，TypeScript 被深度应用于接口类型声明、DTO（数据传输对象）映射与组件 Props 参数约束。通过定义与后端实体严格对应的 Interface，系统构建了端到端的数据类型安全网，极大降低了跨页面数据流转、复杂旅游路线 JSON 解析中的隐式错误风险，同时借助 IDE 的类型推导能力，显著提升了团队协作效率与后期代码重构的安全性。

### Vite 构建机制

项目的前端工程采用 Vite 作为构建工具。区别于传统 Webpack 基于 AST 解析的打包机制，Vite 在开发环境下利用浏览器原生的 ES Modules (ESM) 特性，将模块解析工作交由浏览器端执行，实现了极速的冷启动与毫秒级的模块热替换（HMR）。在生产环境构建时，Vite 底层调用 Rollup 进行代码 Tree-Shaking 与产物压缩，确保最终静态资源的体积最优化。此外，系统充分利用 Vite 的多环境配置文件（.env 系列），动态注入后端 REST API 的基地址，优雅地实现了开发、测试与生产环境的网络解耦。

### Element Plus 与 ECharts

UI 层构建上，管理后台深度集成了 Element Plus 组件库。该库原生支持 Vue3，提供了高可用性的复杂业务组件（如动态表单、高级数据表格、树形权限配置组件等），加速了管理端 CRUD 页面的开发效率。在数据可视化层面，系统引入 ECharts 图表引擎，用于构建管理大屏。通过其底层基于 Canvas/SVG 的高性能渲染能力，系统将复杂的多维数据映射为直观的视觉图表（如展示热点景区客流的折线图、分析用户偏好占比的饼图、以及路线规划的散点统计等），为系统运营者提供了强大的业务决策支持与直观的数据洞察。

## 后端技术基础

### SpringBoot 与 REST API

后端微服务采用 SpringBoot 3.x 作为核心应用框架，凭借其“约定优于配置”的特性，通过各类 Starter 依赖快速构建了基于 IoC（控制反转）与 AOP（面向切面编程）的底层容器。 代码架构严格遵循 Controller-Service-Mapper 三层领域驱动模型。接口设计全面落实 RESTful API 规范，通过 HTTP 动词（GET, POST, PUT, DELETE）精确表达资源操作语义。为保证前后端交互的健壮性，后端封装了全局统一的响应体结构（Result VO），并结合 @RestControllerAdvice 实现了全局异常捕获与细粒度的参数校验（Hibernate Validator），确保对外接口的高内聚与低耦合。

### MyBatis-Plus 与 MySQL

业务数据的持久化层依托 MySQL 8.0 关系型数据库，利用其 InnoDB 引擎提供的 ACID 事务特性，保障用户、订单、权限等核心业务数据的强一致性。在数据访问层，集成 MyBatis-Plus 框架。该框架在保留 MyBatis 原生灵活性的基础上，提供了强大的 CRUD 增强能力与 Lambda 条件构造器。通过面向对象的 LambdaQueryWrapper，系统在避免硬编码 SQL 带来的注入风险的同时，实现了高度类型安全的动态查询。此外，内置的防阻断插件与分页插件，有效降低了冗余的样板代码，提升了数据层的开发效能。

### Redis 缓存机制

为应对旅游旺季的高并发查询挑战，系统引入 Redis 内存级键值数据库作为中间件。Redis 主要承担以下核心职责：

1\. 热点数据缓存：对高频访问的景点详情、首页轮播图等非易变数据进行缓存，大幅降低 MySQL 的磁盘 I/O 压力。

2\. 状态与鉴权管理：结合 JWT 机制，Redis 被用于存储 Token 黑名单与验证码倒计时状态，解决分布式环境下的会话一致性问题。

3\. 接口防刷与限流：利用 Redis 的单线程原子性与过期时间（TTL）特性，实现轻量级的接口防刷机制，保障服务器资源的高效运转与系统整体吞吐量。

### 模拟退火算法理论基础(Simulated Annealing)

模拟退火（Simulated Annealing, SA）是一种概率型全局优化算法，其核心思想是通过控制温度参数逐步降低搜索空间，避免局部最优。算法包含以下要点：

1\. 初始解与初始温度设定。

2\. 邻域解生成（例如景点访问顺序交换）。

3\. 目标函数计算（时间、费用、偏好匹配度）。

4\. Metropolis 准则接受较差解的概率控制。

5\. 温度衰减与终止条件判断。

在本系统中，SA 不是基于理想距离矩阵，而是结合高德路径 API 返回的真实路网成本，增强可执行性。

### RBAC 权限模型

为实现管理端高安全级别的访问控制，系统引入了业界成熟的 RBAC（Role-Based Access Control，基于角色的访问控制）权限模型。该模型通过抽象出“角色”这一中间层，彻底解耦了用户与权限的直接绑定关系。

1\. 细粒度权限定义：将系统资源映射为原子化的权限标识符（如 sys:attraction:add、sys:role:delete）。

2\. 角色授权机制：将权限标识打包赋予特定角色（如“超级管理员”、“内容运营”、“数据审计”）。

3\. 动态赋权拓扑：为用户分配一个或多个角色，实现权限的动态继承。 在实现上，后端通过 Spring Security 配合自定义注解实现接口级别（方法级）的拦截鉴权；前端则结合全局路由守卫（Router Guards）与自定义指令（如 v-hasRole），实现页面菜单和操作按钮的细粒度渲染，最终构建了前后端协同、立体防范的安全治理体系。

### 高德地图 API 调用逻辑

系统深度集成了高德地图的地理服务体系（LBS），以此作为连接算法与现实物理世界的桥梁。其核心调用链路形成了一个闭环：

1\. 地理编码 (Geocoding)：将系统数据库中的文本地址转化为标准化的经纬度坐标（WGS84 转换为 GCJ-02 坐标系）。

2\. 成本矩阵计算：调用高德路径规划 API，动态获取多个景点节点之间的真实路网耗时、通行距离与交通拥堵状况，构建非对称的真实距离矩阵。

3\. 算法赋能：将上述真实交通成本矩阵作为惩罚项和权重输入，注入到后端的模拟退火（SA）算法引擎中。

4\. 渲染展示：将优化后的最优路径序列反演为具体的驾车/步行导航分段数据，返回前端进行地图轨迹的渲染与费用明细展示。 此设计逻辑真正实现了“地图数据驱动算法寻优”，将纯理论的组合优化问题转化为具备极高落地价值的工程解决方案。

# 系统总体设计

## 系统设计原则

1.  模块化与低耦合原则

系统按功能划分为独立模块，降低模块间依赖，便于开发、测试与后期扩展。

1.  高可用与稳定性原则

保证核心接口稳定响应，通过缓存、异常处理、事务保证系统长期可靠运行。

1.  高性能与高并发原则

针对首页推荐、景点查询、路线规划等高频场景做缓存与查询优化，提升并发承载能力。

1.  安全性原则

用户密码加密存储，接口权限拦截，操作日志审计，防止越权与非法访问。

1.  可扩展原则

数据库结构、接口设计、算法逻辑支持后续功能扩展，不重构核心流程。

1.  易用性原则

界面简洁、交互清晰，操作符合用户习惯，降低使用与学习成本。

## 系统架构设计

本系统采用前后端分离 B/S 架构，整体自上而下划分为前端展示层、后端服务层、算法与中间件层、数据持久层四层逻辑架构，各层级职责清晰、低耦合高内聚，层级间通过标准协议交互通信。系统整体技术架构如图 4-1 所示。

1.  前端层

本层为用户交互入口，基于 Vue3 + TypeScript + Vite 工程化框架搭建，搭配 Element Plus UI 组件库、Pinia 状态管理、Axios 网络请求、ECharts 数据可视化组件开发。主要负责页面渲染、前端交互逻辑、表单数据校验、路由权限控制、滚动分页加载、数据可视化展示等功能，通过HTTP/JSON 标准接口协议与后端服务层进行数据双向通信，为普通用户与系统管理员提供可视化操作界面。

1.  后端服务层

本层为系统核心业务逻辑层，基于 SpringBoot 框架开发，严格遵循 MVC 分层设计，分为 Controller、Service、Mapper 三层结构：

Controller 控制层：负责接收前端 HTTP 请求、请求参数合法性校验、接口路由分发、统一封装返回结果；

Service 业务逻辑层：负责核心业务逻辑处理、权限校验、事务控制、业务流程调度、接口异常统一处理；

Mapper 数据访问层：负责底层数据库读写交互、SQL 语句执行与数据映射封装。

同时集成 Spring Security 安全框架与 JWT 令牌认证机制，实现接口身份鉴权、角色权限管控，保障系统接口访问安全。

1.  算法与中间件层

本层为系统能力扩展层，是本旅游平台的特色核心模块，集成缓存、智能算法、第三方服务能力：

Redis 缓存中间件：缓存首页热点景点数据、用户会话信息、推荐结果、路线计算临时数据，大幅降低数据库压力，提升系统并发能力与接口响应速度；

智能算法模块：包含模拟退火智能路线规划算法、基于内容的个性化景点推荐算法，实现平台智能行程规划、个性化景点推送核心能力；

高德地图开放 API：第三方地图服务，提供地理编码、路径距离计算、行程路线规划等地图能力支撑。

本层向上为后端服务层提供算法能力与中间件服务支撑，向下与数据持久层进行数据读写交互。

1.  数据持久层

本层为系统底层数据存储载体，采用 MySQL 8.0 关系型数据库，持久化存储系统全部业务数据，包含用户账号信息、景点基础数据、城市类型数据、用户收藏记录、浏览行为数据、智能路线方案、系统权限角色、操作日志等全量业务数据，保障系统数据安全稳定、可追溯、可持久化存储。

## 数据库设计

数据库设计是系统数据存储与交互的核心，本章主要阐述数据库选型、设计原则、主要数据表结构以及实体关系模型。合理的数据库设计能够保证数据存储的安全性、完整性、一致性，并提升系统查询与业务处理效率。

### 数据库选型

本系统采用 MySQL 8.0 关系型数据库作为数据持久化存储方案。MySQL 具有开源免费、稳定可靠、性能优异、易于维护等特点，支持事务处理、索引优化、联表查询、外键约束及数据备份恢复，能够满足本旅游平台用户信息、景点数据、路线规划、权限管理等全量业务的数据存储需求，同时具备良好的扩展性与兼容性，非常适合毕业设计类项目的开发与部署。

### 设计思路

1.  遵循数据库三大范式

确保数据表结构规范，减少数据冗余，避免数据插入、更新、删除异常，保证数据一致性。

1.  合理设计主键与索引

为每张表设置主键，对高频查询字段建立普通索引、唯一索引，提升数据检索效率。

1.  使用多对多关系处理复杂业务关联

针对景点与类型、景点与标签、用户与收藏、路线与景点等关联关系，采用中间关联表实现标准多对多映射。

1.  支持景点多分类、多标签扩展

建立独立的类型表、标签表及关联表，使景点可归属多个类型、绑定多个标签，满足灵活筛选与推荐需求。

1.  适度冗余提升查询性能

在不破坏数据一致性的前提下，对少量高频展示字段进行适度冗余，减少联表查询次数，优化前端响应速度。

1.  完善系统权限与日志存储

设计 RBAC 权限相关数据表，支持角色、权限、管理员操作日志记录，满足后台安全管理需求。

### 主要数据表

根据业务功能，系统数据表分为用户模块、景点模块、路线模块、系统管理模块四大部分。

1.  用户相关表

- user：用户账号表（账号、密码、状态、创建时间）
- user_profile：用户信息扩展表（昵称、头像、性别等）

- attraction_type_relation：景点 - 类型多对多关联表
- attraction_tag_relation：景点 - 标签多对多关联表

## 后端详细设计与实现

本章节对系统后端服务的整体架构、接口实现、第三方接口集成、缓存策略以及权限控制机制进行详细说明。后端基于主流的分层架构思想进行开发，保证了系统的可维护性、可扩展性与运行稳定性。

### 分层架构设计与 RESTful 接口实现

后端采用经典的 Controller-Service-Mapper 三层架构 进行开发，各层级职责明确、单向依赖，有效降低了模块间的耦合度，提升了代码的可读性与维护效率。

1.  Controller 层：作为系统的访问入口，主要负责接收前端发送的 HTTP 请求，对请求参数进行合法性校验，并将处理结果统一封装后返回给前端。
2.  Service 层：作为核心业务逻辑处理层，负责复杂的业务编排、缓存逻辑协同、权限规则判断以及事务管理。
3.  Mapper 层：作为数据持久层，直接与数据库交互，负责 SQL 语句的执行以及数据库结果与 Java 对象的映射。

通过分层设计，系统实现了 “请求接入 — 业务处理 — 数据访问” 的解耦，为后续功能迭代与测试提供了良好的架构基础。

### Redis 缓存与性能优化

为应对高并发场景下的热点数据查询，降低数据库访问压力，系统引入 Redis 分布式缓存进行性能优化。

系统对热点统计数据、高频查询结果、聚合计算结果等进行缓存处理。查询流程优先访问 Redis 缓存，缓存命中则直接返回；未命中则查询数据库，并将结果写入缓存。

针对后台管理类的实时性要求较高的操作，系统采用 \*\*“写后失效” 策略 \*\*，在数据更新后主动清除对应缓存，保证数据一致性。通过缓存机制，系统显著提升了接口响应速度与并发承载能力。具体缓存流程图跟图 ‎4‑18高并发数据访问流程图一致。

### RBAC 权限管控实现

管理端采用 RBAC（基于角色的访问控制） 模型实现精细化权限管理，通过自定义权限注解 + 拦截器协同完成接口安全校验。

具体校验流程如下：

1.  拦截器解析请求头中的 JWT 令牌，获取当前登录管理员身份。
2.  根据管理员 ID 查询其绑定的角色列表。
3.  根据角色查询对应的权限码集合。
4.  判断当前请求接口所需权限是否在权限集合内。
5.  权限不匹配则直接返回无权限响应，校验通过则放行。

该机制严格遵循最小权限原则，确保不同管理员只能访问其权限范围内的接口与资源，保障了后台管理系统的操作安全性。

## 模拟退火算法实现

智能路线规划是本系统的核心功能，为实现多景点下游览顺序的最优解，系统采用模拟退火算法+高德路径规划2.0API进行路径优化。

### 目标函数设计

算法的优化目标为最小化综合出行代价，目标函数综合考虑三大核心因素：

1.  总行程时间：尽可能缩短路途耗时。
2.  总出行费用：控制交通与门票成本。
3.  偏好权重：通过不同出行偏好动态调整时间与费用权重。

目标函数公式如下：

$$
f(\pi)=\sum_{k=1}^{n}\left(\alpha\cdot t_{\pi_{k-1},\pi_k}+(1-\alpha)\cdot c_{\pi_{k-1},\pi_k}\right)
$$

其中，$t_{i,j}$ 为节点 $i$ 到节点 $j$ 的耗时，$c_{i,j}$ 为节点 $i$ 到节点 $j$ 的交通成本，$\alpha$ 为时间权重。

与系统实现对应的 Java 代码如下：

```java
private double calcRouteCost(List<Integer> order,
							 double[][] timeMatrix,
							 double[][] costMatrix,
							 double timeWeight) {
	double costWeight = 1.0 - timeWeight;
	double total = 0.0;
	int prev = 0;
	for (int node : order) {
		total += timeWeight * timeMatrix[prev][node]
			  + costWeight * costMatrix[prev][node];
		prev = node;
	}
	return total;
}
```

其中时间权重由出行偏好动态确定：

```java
double timeWeight = switch (request.getTravelPreference()) {
	case "经济" -> algorithmProps.getPrefEconomyTimeWeight();
	case "舒适" -> algorithmProps.getPrefComfortTimeWeight();
	default      -> algorithmProps.getPrefModerateTimeWeight();
};
```

### 迭代与降温逻辑

算法在每个温度下进行固定次数迭代，按 Metropolis 准则决定是否接受新解，并在循环末尾执行降温。对应实现如下：

```java
private int[] runSimulatedAnnealing(int nodeCount,
									double[][] timeMatrix,
									double[][] costMatrix,
									double timeWeight) {
	List<Integer> currentOrder = new ArrayList<>();
	for (int i = 1; i < nodeCount; i++) {
		currentOrder.add(i);
	}
	Collections.shuffle(currentOrder);

	double currentCost = calcRouteCost(currentOrder, timeMatrix, costMatrix, timeWeight);
	List<Integer> bestOrder = new ArrayList<>(currentOrder);
	double bestCost = currentCost;

	double temp = normalizeInitialTemp(algorithmProps.getInitialTemp(), algorithmProps.getMinTemp());
	double minTemp = normalizeMinTemp(algorithmProps.getMinTemp());
	double coolingRate = normalizeCoolingRate(algorithmProps.getCoolingRate());
	int iterationsPerTemp = Math.max(algorithmProps.getIterationsPerTemp(), 1);

	Random random = new Random();
	while (temp > minTemp) {
		for (int i = 0; i < iterationsPerTemp; i++) {
			List<Integer> neighbor = randomNeighbor(currentOrder, random);
			double neighborCost = calcRouteCost(neighbor, timeMatrix, costMatrix, timeWeight);
			double delta = neighborCost - currentCost;

			if (delta < 0 || random.nextDouble() < Math.exp(-delta / temp)) {
				currentOrder = neighbor;
				currentCost = neighborCost;
				if (currentCost < bestCost) {
					bestCost = currentCost;
					bestOrder = new ArrayList<>(currentOrder);
				}
			}
		}
		temp *= coolingRate;
	}

	return bestOrder.stream().mapToInt(Integer::intValue).toArray();
}
```

邻域生成采用“随机交换”和“区间反转”两种算子：

```java
private List<Integer> randomNeighbor(List<Integer> order, Random random) {
	if (order.size() < 2) {
		return new ArrayList<>(order);
	}

	if (random.nextDouble() < 0.5) {
		List<Integer> copy = new ArrayList<>(order);
		int i = random.nextInt(copy.size());
		int j = random.nextInt(copy.size());
		while (j == i) {
			j = random.nextInt(copy.size());
		}
		Collections.swap(copy, i, j);
		return copy;
	}

	int i = random.nextInt(order.size());
	int j = random.nextInt(order.size());
	if (i > j) {
		int t = i;
		i = j;
		j = t;
	}

	List<Integer> copy = new ArrayList<>(order);
	while (i < j) {
		Collections.swap(copy, i, j);
		i++;
		j--;
	}
	return copy;
}
```
